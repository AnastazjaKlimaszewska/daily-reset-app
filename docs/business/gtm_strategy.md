# GTM Strategy

## 1. Goal

The purpose of the go-to-market strategy is to define how the first users could discover and validate Daily Reset.

The current student MVP is not focused on generating revenue.

The priority is validating whether users understand and value the core workflow.

## 2. Initial target audience

The first target audience is adults aged approximately 22-35 who experience occasional decision fatigue, low energy or mental overload.

Potential early users may include:

- students,
- young professionals,
- remote workers,
- people using productivity or self-care applications.

## 3. Initial distribution channels

The first validation can use low-cost channels such as:

- direct sharing with test users,
- student communities,
- productivity and self-care communities,
- social media posts,
- personal networks.

The goal is not mass acquisition.

The goal is obtaining feedback from a small number of relevant users.

## 4. Validation approach

Early users should be asked to complete the main Daily Reset flow.

The following questions should be validated:

- Is the check-in understandable?
- Does the recommendation feel relevant?
- Is the number of choices appropriate?
- Does the user understand what to do next?
- Would the user return to the application?
- Is history useful?
- Are statistics understandable?

## 5. Early success metrics

The first validation may track:

- number of completed check-ins,
- percentage of check-ins followed by an action,
- number of returning users,
- most frequently selected actions,
- qualitative user feedback.

## 6. Positioning message

Daily Reset should be positioned as:

"A lightweight self-care decision-support tool that helps you choose one realistic action based on how you feel right now."

## 7. Monetization hypothesis

Monetization is not part of the current student implementation.

Possible future models could include:

- free basic version,
- premium analytics,
- personalized recommendation libraries,
- optional subscription features.

These hypotheses require validation before implementation.

## 8. Launch approach

The MVP should be launched as a public web application.

The initial launch process is:

1. publish the application on Vercel,
2. share the link with a small number of users,
3. observe the user flow,
4. collect feedback,
5. identify the main friction points,
6. update the product only after validation.

## 9. Risks

Main go-to-market risks include:

- unclear differentiation from habit and wellness apps,
- low motivation to return,
- recommendations being perceived as too simple,
- insufficient evidence that users need a separate tool for this problem.

## 10. GTM principle

The project follows a Lean First approach.

The product should be validated with a small audience before investing in additional infrastructure, monetization or advanced features.
