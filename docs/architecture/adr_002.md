]# ADR 002: Use Next.js with React and TypeScript

## Status

Accepted.

## Context

Daily Reset requires a modern frontend architecture that supports:

- interactive user input,
- local application state,
- reusable UI structure,
- automated testing,
- production deployment,
- future extensibility.

The application does not currently require a separate backend.

## Decision

Use:

- Next.js,
- React,
- TypeScript.

Next.js provides the application framework and production build process.

React provides the component model and interactive state management.

TypeScript provides static typing for:

- check-in values,
- classified states,
- recommendation objects,
- persistence entities.

## Consequences

Advantages:

- clear project structure,
- strong TypeScript support,
- modern React development model,
- simple deployment,
- compatibility with automated testing,
- easy future extension.

Trade-offs:

- the framework provides more capabilities than the current MVP immediately needs,
- some architecture decisions must remain intentionally simple to avoid unnecessary complexity.

## Current usage

The current application uses:

- Next.js App Router,
- React client components,
- TypeScript,
- Tailwind CSS.

The main application interface is currently implemented in:

`app/page.tsx`

Domain and persistence logic are separated into:

- `lib/recommendations.ts`,
- `lib/db.ts`,
- `lib/storage.ts`.

## Decision rationale

The selected stack provides enough technical depth for the project while keeping the implementation manageable and aligned with the current narrow MVP scope.
