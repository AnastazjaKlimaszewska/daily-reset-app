# Data Model

## 1. Purpose

The Daily Reset MVP requires structured local data persistence.

The application stores two main types of data:

- CheckIn
- CompletedAction

Data is stored in IndexedDB using Dexie.

## 2. CheckIn entity

A CheckIn represents one completed Daily Reset check-in.

### Fields

#### `id`

Unique identifier of the check-in.

Type:

`string`

#### `createdAt`

Date and time when the check-in was created.

Type:

`string`

#### `energy`

Current energy level selected by the user.

Allowed values:

- `low`
- `medium`
- `high`

#### `mood`

Current mood selected by the user.

Allowed values:

- `low`
- `neutral`
- `good`

#### `mentalLoad`

Current level of mental load selected by the user.

Allowed values:

- `low`
- `medium`
- `high`

#### `availableTime`

Amount of time currently available to the user.

Allowed values:

- `5`
- `10`
- `20`

The value represents minutes.

#### `classifiedState`

State generated by the deterministic classification logic.

Allowed values:

- `recovery`
- `balanced`
- `active`

## 3. CompletedAction entity

A CompletedAction represents one recommendation completed by the user.

### Fields

#### `id`

Unique identifier of the completed action.

Type:

`string`

#### `checkInId`

Identifier of the CheckIn connected to the action.

Type:

`string`

#### `activity`

Name of the completed activity.

Type:

`string`

#### `category`

Category assigned to the activity.

Type:

`string`

Possible categories depend on the recommendation set.

Examples may include:

- rest,
- movement,
- focus,
- environment.

#### `completedAt`

Date and time when the activity was completed.

Type:

`string`

## 4. Relationship

A CompletedAction is connected to the CheckIn that generated the recommendation.

The relationship uses:

`CompletedAction.checkInId`

which references:

`CheckIn.id`

In the current user flow, one selected recommendation is completed for a generated reset.

## 5. IndexedDB structure

The database is defined in:

`lib/db.ts`

Dexie is used as the IndexedDB abstraction layer.

The database contains two main tables:

- `checkIns`
- `completedActions`

Storage access is implemented in:

`lib/storage.ts`
