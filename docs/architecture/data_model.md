# Data Model

## 1. Purpose

The Daily Reset MVP needs structured local data persistence.

The application stores two main types of data:

CheckIn and CompletedAction.

The data is stored in IndexedDB using Dexie.js.

## 2. CheckIn entity

A CheckIn represents one completed daily check-in.

### Fields

`id`

Unique identifier of the check-in.

Type: string

`createdAt`

Date and time when the check-in was created.

Type: string

`energy`

Current energy level selected by the user.

Allowed values:

low, medium, high

`mood`

Current mood selected by the user.

Allowed values:

low, neutral, good

`mentalLoad`

Current level of mental load.

Allowed values:

low, medium, high

`availableTime`

Amount of time the user currently has available.

Allowed values:

5, 10, 20

The value represents minutes.

`classifiedState`

State generated by the deterministic classification logic.

Example values:

recovery, balanced, active

## 3. CompletedAction entity

A CompletedAction represents one micro-action completed by the user.

### Fields

`id`

Unique identifier of the completed action.

Type: string

`checkInId`

Identifier of the CheckIn connected with the action.

Type: string

`activity`

Name of the completed activity.

Type: string

`category`

Category of the activity.

Example values:

rest, movement, focus, environment

`completedAt`

Date and time when the activity was completed.

Type: string

## 4. Relationship

One CheckIn can have zero or one CompletedAction in the initial MVP.

The relationship is created using:

`CompletedAction.checkInId`

which references:

`CheckIn.id`
