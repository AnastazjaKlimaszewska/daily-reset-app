# ADR 001: Use localStorage for data persistence

## Status

Accepted

## Context

Daily Reset needs to remember completed activities after the user refreshes or reopens the page.

For the MVP, the application does not require user accounts, synchronization between devices or a shared database.

## Decision

The application will use browser localStorage to store the history of completed activities.

## Reasons

localStorage is sufficient for the current scope because:

- the project is a small MVP,
- no backend is required,
- no user authentication is required,
- data can remain on the user's device,
- implementation is simple and easy to maintain.

## Consequences

The application can remember completed activities after a page refresh.

However, the data is available only in the browser where it was saved. It will not synchronize between devices and may disappear if the user clears browser data.

If the project grows in the future, localStorage can be replaced with an external database.
