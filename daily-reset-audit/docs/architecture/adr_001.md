# ADR 001: Use localStorage for Prototype Persistence

## Status

Superseded by ADR 003.

## Context

The initial Daily Reset prototype required a simple way to persist completed activity history in the browser.

At that stage, the application scope was very small and the data model was limited.

## Decision

Use `localStorage` for the first prototype version.

This allowed the prototype to:

- store simple history,
- persist data between refreshes,
- avoid backend infrastructure,
- remain easy to implement.

## Consequences

Advantages:

- very low implementation complexity,
- no backend required,
- easy browser persistence.

Limitations:

- weak structure for multiple related entities,
- less suitable for querying and scaling local data,
- harder to maintain as the data model grows.

## Superseded decision

This decision was replaced by:

`ADR 003: Use IndexedDB with Dexie for Local Persistence`

The current MVP does not use localStorage as its primary persistence layer.
